# Lease Accounting Reconciliation & Data Quality Checker

A SQL-based source-to-target validation project. It compares lease **source data**
(leases and monthly charges) against **target data** (general-ledger postings) and
reports data-quality defects. All data is synthetic, generated by the script, so no
real or sensitive data is used.

## What it validates

| Check | Data-quality dimension | SQL technique |
|-------|------------------------|---------------|
| C1 | Completeness: source charges with no ledger posting | LEFT JOIN + IS NULL |
| C2 | Accuracy: posted amount differs from source | INNER JOIN + ABS difference |
| C3 | Uniqueness: same charge posted twice | GROUP BY + HAVING COUNT(*) > 1 |
| C4 | Validity: NULL / non-positive rent, end date before start date | WHERE + CASE |
| C5 | Consistency: ledger postings with no source charge (orphans) | LEFT JOIN from target side |
| C6 | Timeliness: posted more than 5 days after charge date | date arithmetic |
| C7 | Reconciliation: per-lease source total vs ledger total | subqueries + SUM + GROUP BY + COALESCE |

Defects are seeded on purpose (5 missing, 4 wrong amount, 3 duplicates, 3 invalid
leases, 2 orphans, 2 late postings) so each check has something to catch.

## Run

```bash
pip install openpyxl
python lease_recon_checker.py
```

Output: a PASS/FAIL summary in the console and `lease_recon_report.xlsx`
(a Summary sheet plus one sheet of defect rows per failing check).

## Tech

Python, SQL (SQLite), openpyxl (Excel report).
